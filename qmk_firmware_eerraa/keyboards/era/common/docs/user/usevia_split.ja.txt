======================================================================
Split Official VIA Guide
======================================================================

この文書は公式 VIA（https://usevia.app）を直接使用するときの案内です。通常の設定や高度な編集、自動更新されるステータス表示には https://usekb.cc と各メニュー横の Help を推奨します。

■ 公式 VIA の開始

ご使用中のキーボードに合った配布 ZIP 内の JSON を使用してください。

1. https://usevia.app にアクセスします。
2. SETTINGS で Show Design tab をオンにします。
3. DESIGN -> Load Draft Definition で現在 USB に接続するユニットの VIA JSON を読み込みます。L ファイルは左ユニット用、R ファイルは右ユニット用です。
4. DUAL-HOST で左右のユニットをそれぞれ USB に接続する場合は、L/R 両方の JSON を読み込みます。
5. CONFIGURE で KEYMAP、LIGHTING、FEATURE、TAPDANCE、SYSTEM を設定します。

TAPDANCE 入力欄に直接 keycode を入力するときは、同じフォルダーの via_keycodes.txt を参照してください。キーマップを保管するには VIA の SAVE + LOAD でバックアップしてください。

通常のアップデートでは同じ保存形式の有効な設定が維持されますが、保存形式の変更や無効な保存データによって初期化されることがあります。Reset.uf2 は通常のアップデートではなく、インストール後の初回に一度だけ現在の設定をすべて消去する全機能ファームウェアです。初期化後はそのまま使用でき、新しい設定は再起動後も維持されます。同じファイルを再度インストールすると再び初期化されます。ケーブルを外して左右の両方を初期化する必要があります。バックアップと復旧の手順は配布 ZIP の readme.txt に従ってください。

■ VERSION

CONFIGURE -> SYSTEM -> VERSION は現在 USB で接続しているユニットのファームウェアバージョンを YYMMDDRn 形式で表示し、VIA から変更することはできません。左右のユニットは同じバージョンを使用する必要があります。

■ MATRIX TEST

VIA の Matrix Test は現在の USB ユニットが構成する物理マトリックスの押下状態を表示します。VIA Raw HID を使用できるホストプログラムは現在押されているマトリックス位置を取得できるため、信頼できる PC で使用してください。

■ TAPDANCE

CONFIGURE -> TAPDANCE で TD0~TD7 を設定した後、KEYMAP で同じ TD 番号を希望の位置に配置します。TD キーを実際のキーマップに配置するまでは、設定した動作は実行されません。

- On Tap：短くタップしたときの keycode
- On Hold：長く押したときの keycode
- On Double Tap：Term 内に二回タップしたときの keycode
- Tap+Hold：一回タップした後に続けて長く押したときの keycode
- Term：複数の入力動作を判定する時間。公式 VIA では 100~500ms を 20ms 単位で選択します。

Legacy で On Double Tap と Tap+Hold を空欄にしたスロットは、キーを離した瞬間にタップが入力され、Term はホールド判定にのみ使われます。On Double Tap を設定すると、二回目のタップを離した瞬間に入力されます。

公式 VIA は Legacy モードの基本動作と Term のみを編集します。高度なモードや不明なモード値のスロットには usekb.cc の案内のみを表示し、基本動作も編集しません。入力モードの変更、独立したホールド時間、別のキー押下時のホールド設定は https://usekb.cc で使用してください。公式 VIA を開いたり定義を読み込んだりしただけでスロットのモードや動作が変わることはありません。

■ SOCD

CONFIGURE -> FEATURE -> SOCD で反対方向の二つのキー（左/右、上/下）を指定し、二つのキーを一緒に押しているときに PC へ送るキーを Mode で選びます。

- Last Input：後から押したキーのみを送ります。そのキーを離すと、まだ押しているもう一方のキーがすぐに再入力されます（スナップタップ）。初期値です。
- Neutral：どちらのキーも送りません。
- First Input：先に押したキーを維持します。
- Left/Up Priority, Right/Down Priority：押した順序に関係なく、指定した側を送ります。

キーには通常キーまたは modifier キーを指定してください。PC へ出力されるキーを基準に判定するため、Tap Dance やマクロが出力したキーにも適用されます。一組の二つの欄に同じキーを入れると動作せず、オンになっている二組が有効な同じキーを共有すると両方の組とも動作しません。オフになっている組のキー指定は他の組を妨げません。DUAL-HOST では二つのユニットがそれぞれ PC へ送るため、一組の二つのキーが同じユニットにある場合のみ適用されます。一部のゲームや大会では SOCD の使用が制限されているため、規定を確認してください。

■ KKUK

CONFIGURE -> FEATURE -> KKUK で使用します。通常キーを二つ以上押し続けると、押されているキーのまとまりを Delay/Repeat 設定に従って周期的に離して押し直します。たとえば A、S、D を押し続けると、通常の「asdddd...」という自動リピートではなく「asdasdasd...」のように入力されます。文字列マクロやマトリックスの ghosting 防止機能ではありません。オンになっていて有効かつ他の組と重ならない SOCD ペアのキーのみが繰り返し対象から除外され、オフの組や無効・競合している組のキーは除外されません。

■ DEBOUNCE

CONFIGURE -> FEATURE -> DEBOUNCE でスイッチのチャタリングフィルターを調整します。初期値は Balanced、5 ms です。一回押したのに複数回入力される症状があるときだけ関連する時間を少しずつ増やし、問題がなければ初期設定を維持してください。

■ TAPPING

CONFIGURE -> FEATURE -> TAPPING で Mod-Tap/Layer-Tap のタップ・ホールド判定を調整します。Tapping Term の初期値は 200 ms です。短いほどホールドが早くかかりますが速いタイピングが意図しないホールドと判定されることがあり、長いほど安定しますがホールドの反応は遅くなります。

- Permissive Hold：別のキーを押して離すまでタップ・ホールドキーを押し続けていると、ホールドと判定します。
- Hold On Other Key Press：別のキーを押した瞬間にすぐホールドと判定します。より高速ですが、ロールオーバー打ち（前のキーを離す前に次のキーを押す打鍵）では意図したタップがホールドになることがあります。
- Retro Tapping：Term を超えて押していても、そのあいだに別のキーを押さなければ、キーを離したときにタップを入力します。

■ MOUSE

整数単位の精密な入力は usekb.cc の詳細設定で提供しています。公式 VIA は最も近いプリセットを表示し、参照しただけで精密な値を変えることはありません。ホイール加速は時間が 0 のとき Off、それ以外は目標速度を基準に Mild/Strong を表示します。プリセットを選択するとその設定に変更されます。

CONFIGURE -> FEATURE -> MOUSE で Mouse Key の動作を調整します。キーマップに Mouse Key がなければ入力には影響しません。各値が互いに影響するため、一度に一つずつ調整してください。

- Cursor Acceleration：開始速度から最高速度まで加速する時間。Off のときは固定速度。
- Cursor Start Speed / Top Speed：加速開始/終了時のワンステップあたりの移動距離。
- Cursor Speed：Acceleration が Off のときのワンステップあたりの移動距離。
- Cursor Steps Per Second：秒あたりのカーソル移動ステップ数。
- Wheel Rate：秒あたりのスクロールステップ数。
- Wheel Acceleration：押しているあいだのスクロール加速の度合い。

■ ROLLOVER / NKRO

CONFIGURE -> FEATURE -> NKRO で NKRO のオン・オフを切り替えます。初期値はオフ（6KRO）で、オンにすると押したキーをすべてレポートします。オンにした後に古い BIOS/KVM やブートメニューがキーボードを認識しない場合は、再度オフにしてください。

■ LIGHTING

CONFIGURE -> LIGHTING の Per-Key RGB で明るさ、エフェクト、速度、色を調整します。Badge はバッジ LED の役割を決めます。

- RGB-Only：選択した RGB エフェクトをバッジ領域にのみ適用します。
- Indicator：RGB Effect / Caps Lock / Scroll Lock / Num Lock のなかから表示する状態を決めます。RGB Effect にするとバッジは RGB エフェクトをそのまま表示します。
- Indicator-Only：バッジ領域をロック表示専用として使用します。通常の RGB エフェクトは表示しませんが、リンク・同期の一時的な STATUS 通知は表示されることがあります。
- Indicator Brightness / Indicator Color：Lock 表示の明るさと色を決めます。

■ SYSTEM

CONFIGURE -> SYSTEM にはスプリット専用の SYNC と LINK、および SLEEP と BOOT があります。

SYNC:
三つの項目はすべて初期値が On で、互いに独立した設定です。
- EEPROM SYNC：左右のユニットの保存設定を同期します。同期作業が表示されているあいだ STATUS は青色になります。INPUT SYNC と RGB SYNC の前提条件ではありませんが、左右のキーマップと設定を揃えて維持するにはオンにしておくことを推奨します。
- INPUT SYNC：左右のユニットを両方とも PC に接続した DUAL-HOST でレイヤー状態とキー入力判定を共有し、一つのキーボードのように動作させます。
- RGB SYNC：DUAL-HOST でリアクティブエフェクトを含め、左右のユニットのライティングを揃えます。
INPUT SYNC と RGB SYNC は DUAL-HOST での共有範囲を制御します。片側のみを USB に接続した HOST-PEER では、この二つの設定をオフにしても入力とライティングの伝達は維持されます。

LINK:
- High：460800 bps / 1 ms（初期値）
- Medium：230400 bps / 2 ms
- Low：115200 bps / 4 ms

現在の実行・保存速度と適用結果は usekb.cc Custom アプリで確認してください。公式 VIA の LINK 選択値は適用完了を意味しません。LINK の値を選んだ後に Apply を使用します。接続されている左右のユニットが合意したタイミングで一緒に速度を切り替え、キーボードの再起動や USB 切断は行いません。

TOMAK-TKL・TOMAK79H・TOMAK79S は RGB 領域全体に一時的な STATUS を表示します。
- 緑色 1 回：コマンドを受け取ったユニットの Apply 成功。実行・保存速度がすでに一致している場合も含みますが、反対側の保存まで確認したという意味ではありません。
- 赤色 1 回：要求の処理不可・キャンセル・失敗。
- 両側の短い緑色 2 回：速度探索後のリンク復旧。
- 長い赤色 3 回：リンク速度の失敗に伴う Low 復旧警告。繰り返す場合はケーブルを点検または交換してください。この表示だけで原因を確定することはできません。
- 青色：EEPROM 同期作業。
RGB スリープ中は STATUS を表示しません。通常のロックインジケーターのユーザー指定色と STATUS の色は別の意味を持ちます。

SLEEP:
RGB Sleep は初期値が On です。オフにするとアイドル時間だけでなく、USB スリープやホスト喪失を含む自動 RGB スリープ全体が無効になります。On のときのみ時間設定が表示され、最後の入力から 1/3/5/10/30/60 分のなかから選択します。初期値は 10 分です。トグルをオフにしても時間値は保持されます。

BOOT:
Jump To BOOT をオンにすると現在のユニットのブートローダー進入を要求します。実行後に常にオフの値で見えるのは正常です。

■ EEPROM CLEAN

三つの確認トグルには時間制限がありません。オンにしたトグルをオフにすると該当の確認のみが取り消され、再起動すると確認状態はすべて消去されます。

CONFIGURE -> SYSTEM -> EEPROM で三つの確認トグルをすべてオンにすると CLEAN が要求されます。互いに正常に通信している左右のユニットは合意を経て一緒にキーマップ・マクロ・すべての設定を初期化して再起動します。切り離されているユニットはそれぞれローカル CLEAN を実行します。実行前に VIA SAVE + LOAD でキーマップをバックアップしてください。
